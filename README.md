# 运输船 · 甲板交锋 / DECKFIRE

浏览器里的第一人称团队竞技。一条 24 × 51 米的货轮甲板，三条通道，最多 8 对 8。
Three.js 单页 ES Module，无框架、无构建步骤（离线单文件版有独立构建脚本）。

**一句话定义**：用诚实的弹道扩散和 0.30 秒的 TTK，决出谁先在三条通道里架稳角。

---

## 1. Fun Hypothesis

> **这游戏好玩的核心是：准星此刻诚实地告诉你「我有多稳」，而你必须在它变稳之前开枪。**

这条假设不是装饰，它在代码里有一个可验证的落点：准星的开合距离由**真实的射击扩散值**驱动，
不是美术做的假抖动。

```js
// main.js —— 准星 gap = 真实扩散角 × 焦距像素
const focalPixels = innerHeight / (2 * Math.tan(camera.fov * Math.PI / 360));
$('cross').style.setProperty('--gap', Math.min(38, s.spread * focalPixels) + 'px');
```

`spread` 来自 `gunplay.js` 的 `firingCone()`，它叠加了：静止精度、移动惩罚、蹲下/开镜收益、
连发累积扩散（bloom）、以及按枪型的后坐爬升与随机左右偏转。
**结论：玩家看到的每一次准星张开，都对应一组真实数值。** 这条不能破。

## 2. Design Pillars

改动前先对照这三条，任何一条不服务就砍掉。

| # | Pillar | 判断标准 | 违反示例 |
|---|--------|---------|---------|
| 1 | **手感诚实** | 所有视觉/音频反馈必须对应真实数值，不做假的抖动、假的增益 | 给准星加装饰性回弹；击杀播报与真实命中不一致 |
| 2 | **三线短交火** | 任意两点间路程 ≤ 6 秒；架枪窗口 ≤ 1.2 秒 | 加一条需要 8 秒绕行的纵深通道 |
| 3 | **武器是可把玩的对象** | 每把武器有一个「不为战斗、只为手感」的动作或特征 | 砍掉蝴蝶刀的 flourish；抹掉准星工坊 |

Pillar 3 是这个项目唯一真正原创的东西（CS / CF / Valorant 都没有）。
它的实现证据：蝴蝶刀的 `inspect / flourish / fidget` 三段动作 + 独立拔刀音、准星工坊的
1:1 物理像素渲染 + Valorant 代码导入导出、四把近战的差异化手感曲线。
**这是彩蛋还是支柱，取决于后面所有决策怎么站队。我站「是支柱」。**

## 3. 核心循环：三层钩子与现状

| 层级 | 时间尺度 | 设计意图 | 现状 | 缺口 |
|---|---|---|---|---|
| **Moment-to-moment** | 0–30 秒 | 动作 → 反馈 → 奖励 | **A 级**。开火 → 曳光/弹壳/枪口焰 → 命中十字 + 爆头音 → 击杀徽章 | 无 |
| **Session loop** | 3–10 分钟 | 目标 → 张力 → 结果 | **C 级**。有比分和计时，但节奏平权 | 死亡无代价、计时器是死 UI（见 §8） |
| **Long-term** | 小时–周 | 进阶 → 保留钩子 → 社交 | **F 级**。无进度、无解锁、战绩不落盘 | 未开始 |

Moment-to-moment 这一层是工程的强项：距离衰减音效（`1/(1+dist×0.09)` + 左右 pan）、
伤害方位指示、屏幕抖动、血迹与弹孔、弹壳抛壳、48 发曳光池、倒地死亡动画。
**这一层不用改，改它会毁掉已有的说服力。**

## 4. 数值表与 rationale

> 下列数字全部由 `node tools/ttk.mjs` 从 `arsenal.js` 实测生成，与运行时同一套公式。
> 改数值后请重跑，不要手算。

### 4.1 护甲模型

```
absorb = min(护甲剩余, 伤害 × (1 - 穿甲系数))
hp    -= 伤害 - absorb
```

护甲 100 点，AK 每发只吸走 8 点 → 一场交火内护甲**几乎不会被打空**。
所以护甲的实际语义是：**一个固定的乘法减伤（1 - 穿甲系数），而不是会被消耗掉的资源。**
只有在一局活很久、连续换命的情况下，护甲值才会掉到能改变击杀枪数的区间
（例：护甲 ≤ 22 时，M4 爆头才会一枪致死）。这是可接受的涌现结果，但 HUD 上
「护甲 100」这个数字因此**信息量很低**。

### 4.2 枪械（满血满甲，躯干命中）

| 武器 | 5m | 20m | 30m | 满甲爆头 | 射速间隔 | 定位 |
|---|---|---|---|---|---|---|
| AK-47 | 4 枪 / 0.32s | 4 枪 / 0.32s | 4 枪 / 0.32s | **1 枪 128** | 0.11s | 一击定音，代价是抖动 |
| M4A1 | 4 枪 / 0.30s | 4 枪 / 0.30s | 4 枪 / 0.30s | 2 枪 91.8 | 0.10s | 稳定输出，不能一枪爆头 |
| AWM | **1 枪 / 0.00s** | 1 枪 / 0.00s | 1 枪 / 0.00s | 1 枪 245 | 1.43s | 躯干即杀，开镜收紧 0.15s，拉栓 1.43s |
| MP5 | 6 枪 / 0.38s | 7 枪 / 0.45s | 8 枪 / 0.53s | 2 枪 63.7 | 0.07s | 近身压制（14m 内） |
| 沙漠之鹰 | 3 枪 / 0.46s | 3 枪 / 0.46s | 3 枪 / 0.46s | 1 枪 164 | 0.23s | 副武器，弹尽时的答案 |

**AK / M4 的分工成立**：躯干 TTK 只差 16 毫秒（一帧），差异化全部压在
「能否一枪爆头」上——AK 满甲爆头 128 致死，M4 是 91.8 不致死。
这是 CS 的正统分工轴，不是偷懒。代价见 §8 第一条：**玩家不知道 91.8 为什么没死。**

### 4.3 近战（正面满甲）

| 武器 | 轻击 | 重击 | 轻 CD | 重 CD | 轻 / 重距离 | 拔刀 |
|---|---|---|---|---|---|---|
| 军刀 | 45.4 → 3 刀 | 100.8 → **1 刀死** | 0.37s | 0.86s | 2.05 / 1.95 | 0.10s |
| 尼泊尔军刀 | 61.2 → 2 刀 | 121.5 → **1 刀死** | 0.43s | 0.90s | 2.20 / 2.18 | 0.11s |
| 马来剑 | 45.8 → 3 刀 | 103.8 → **1 刀死** | 0.29s | 0.80s | 2.35 / 2.30 | 0.10s |
| 蝴蝶刀 | 50.7 → 2 刀 | 92.9 → **不杀（剩 7.1）** | 0.38s | 0.77s | 2.13 / 2.05 | 0.22s |

背后的倍率：**背刺 ×1.8**、**头部 ×1.3**。所以正面 1 刀死的重击，背刺伤害是 181，
头部重击 131 —— 倍率对已经超阈值的一刀杀没有意义（见 §8）。

### 4.4 Tuning Levers

| 我想改变 | 改这里 | 连带影响 |
|---|---|---|
| 某把枪的击杀枪数 | `arsenal.js` 的 `damage` × `armor` | 同时改变爆头倍率的实际收益 |
| 交火节奏（快/慢） | `rpm` / `interval` | 会同时改变后坐累积速度（`recordShot` 用 interval 判断连发窗口） |
| 远近交战权重 | `falloff` 的 `from / to / floor` | 必须验证 floor 是否真的跨过击杀枪数阈值 |
| 移动交战惩罚 | `base` / `moving` | 准星 gap 会同步变化（这是设计意图，别抵消它） |
| AI 强度 | `skills.*` | `head` 是**每一枪**的瞄头概率，改动极敏感 |
| 对局时长 | `match-rules.js` 的 `goal` / `duration` | 两者必须同时校验，否则其中一个会变成死 UI |

**数值纪律**：没有 rationale 的数字不允许进 `arsenal.js`。本版全部数字已过
`tools/ttk.mjs` 验证；任何未跑过 playtest 的新数值，必须在提交信息里标 `[PLACEHOLDER]`
并写明假设与验证路径。

## 5. 经济模型：Sources & Sinks

| 项 | 内容 |
|---|---|
| **Sources**（玩家获得） | 击杀得分 +1、连杀计数（仅视觉）、出生即满装（无购买阶段） |
| **Sinks**（玩家消耗） | **无** |
| 结论 | 因为没有可积累资源，**通胀风险 = 0**，也**没有经济深度** |

这是一个**明确的设计选择**，不是遗漏：核心循环在没有二级系统时本身必须好玩，
所以第一版不做购买/经济是正确的。但当核心循环已经过线（它过了），
**下一个系统必须先是一个 sink，而不是又一个 source。**

第一个该加的 sink（按 ROI 排序，都还没做）：
1. **死亡代价**：连死 2 次关闭该出生点 8 秒 —— 消耗的是「位置」，不是货币。
2. **武器熟练度**：使用次数换外观/手感变体 —— 消耗的是「时间」，能同时补 Long-term 层。

## 6. 系统交互矩阵

每对系统交互都必须被显式分类，不允许「不知道会发生什么」。

| 交互 | 表现 | 判定 |
|---|---|---|
| AWM × 开镜 | 玩家开镜后 0.15s 收到最紧散布，AI 重新瞄准和拉栓后也等 0.15s | 快开镜仍可开火，稳定后更准 |
| AWM × 木箱 | 单层木箱保留 60% 伤害，满甲躯干约 66.9 | 正面躯干一枪，隔箱需要补枪 |
| AWM × 护甲 | 111.6 伤害穿透 97%，护甲只吸 3.45 | **intended**：狙击无视护甲符合直觉 |
| M4 爆头 × 满甲 | 91.8，不致死 | **acceptable，但缺反馈** → 见 §8 |
| MP5 衰减 × 交战距离 | 14m 内 6 枪，20m 起 7 枪，30m 8 枪 | **intended**，但有效区间窄（§8） |
| 沙鹰衰减 × 击杀枪数 | 任何距离都是 3 枪 | **bug**：衰减不改变任何结果，只增加复杂度 |
| 玩家重击 × 前摇 | 玩家 0 秒判定；AI 有 0.22–0.25s windup | **bug**：不对称，刀战玩家碾压 |
| 重击距离 × 轻击距离 | 四把刀的重击距离**全部小于**轻击距离 | **bug**：与「重击更远更痛」的心智模型冲突 |
| 出生保护 × 近战 | `damage()` 直接 return，无任何提示 | **acceptable**，但玩家会读成「打不中」 |
| 管道单通道 × 全图视野 | 侧翼路线价值趋零 | **需改**：管道被 AWM 单向收割 |
| 蝴蝶刀重击 × 轻击连打 | 重击 92.9 不杀、距离更近、CD 更长 | **bug**：重击键是死键 |

## 7. Playtest：先定义「坏掉长什么样」

**没有失败信号的 playtest 等于没做。** 当前没有埋点，所以第一轮只能录屏 + 手记。
以下每一条都是可观测的事件，不是感觉。

| 层级 | 失败信号 | 观察方法 | 判定阈值 |
|---|---|---|---|
| Session loop | 玩家在第 3 分钟后出现无目的游走 | 雷达轨迹原地绕圈 | 连续 > 20 秒无接敌意图 |
| 武器选择 | 连续 3 局全员选 AWM | 对局结算与装备记录 | AWM 出场率 > 60% |
| 难度曲线 | normal 被碾压或碾压 AI | 单局 KD | KD < 0.6 或 > 3.0 |
| 近战 | 重击使用率极低 | 刀战局录像 | 重击次数 / 总挥击 < 10% |
| 反馈 | 玩家把「M4 爆头没死」报告为 bug | 口述复盘 | 出现 ≥ 2 次 |
| 可读性 | 玩家说不出自己是怎么死的 | 死后追问 | 无法指出受击方向 ≥ 3 次/局 |

配套的验收标准（这三条过不了，就不该往下加系统）：
1. 新玩家不看说明能在 60 秒内击杀第一个 AI。
2. 老玩家能说出「AK 和 M4 我该选哪个、为什么」。
3. 任何一次死亡，玩家能在 2 秒内指出方向与武器类型。

## 8. 已知缺口（诚实清单）

### P0 · 数值层
| 问题 | 证据 | 建议 | 状态 |
|---|---|---|---|
| M4 满甲爆头 91.8 不杀，但没有任何护甲反馈 | `tools/ttk.mjs` 输出 | 加「护甲抵挡」火花 + 短促金属音，让 91.8 可被读懂 | 待做 |
| AWM 躯干一枪死，且无经济代价 | 111.6 > 100 | 不动伤害（符合狙击幻想），改代价：备用弹 20 → 10、拉栓期间锁镜 0.55s | `[PLACEHOLDER]` 需 playtest |
| 沙鹰衰减数值无效 | 18m 与 36m 都是 3 枪 | 删掉 `falloff.deagle`，或把 floor 压到 0.58（变 4 枪） | 待决 |
| 尼泊尔军刀被马来剑完全支配 | 重击：马来 0.80s/2.30m 一刀杀 vs 尼泊尔 0.90s/2.18m 一刀杀 | 给尼泊尔唯一性：最慢但最痛→无意义；改为**最远重击 + 最高轻击伤害**并回调马来剑重击 | 待做 |
| 蝴蝶刀重击不杀且距离更近 | 92.9，reach 2.05 < 轻击 2.13 | 重击 108 → 117（117×0.86 = 100.6，恰好跨过阈值） | 待做 |
| 四把刀的重击距离全部 < 轻击距离 | 军刀 1.95/2.05 等 | 所有 `heavyReach` ≥ `reach` + 0.15 | 待做 |
| 玩家重击无前摇，AI 有 0.22–0.25s | `match.js` 玩家近战分支直接 `damage()` | 给玩家重击加 0.16–0.22s 前摇（与 CD 分离） | 待做 |

### P1 · 循环层
- **计时器是死 UI**：6v6 目标 50 杀、重生 2.5 秒，13 个单位在 24×51 米的船上，
  稳态击杀率 3–5 秒一条 → 50 杀约 3–5 分钟到顶，菜单上的 `10:00` 永远不会跑完。
  `[PLACEHOLDER]` 估算依据为地图面积 / 交火密度，需 playtest 实测。
  建议：改成「计时决胜」或「上半场 5 分钟 + 比分决胜」，让倒计时成为真资源。
- **难度阶梯只有两档可用**：`hell` 的 `head: 0.50` 意味着每一枪有 50% 概率瞄头，
  叠加 `sight: 70`（51 米甲板 = 全图视野），AI 击杀窗口约 0.1 秒，而玩家最短 TTK 是 0.30 秒。
  这个交换里玩家没有可用手段，地狱不是「难」而是「抽签」。
  正确顺序是**先减信息再加准**：`hell.sight 70 → 43`、`hell.head 0.50 → 0.22`，
  并把 `match.js` 的受击情报共享半径 16 → 6（当前一名队员挨打，16 米内队友全部获得敌人坐标）。

### P2 · 长线层（未开始）
进度 / 解锁 / 成就 / 每日挑战 / 战绩持久化（当前 `localStorage` 只存设置与准星）/ 赛季。
1v1 好友房已是服务端权威模拟（60Hz 步进、30Hz 快照），但移动没有客户端预测，
手感会重 50–80ms。`[PLACEHOLDER]` 需实测。

## 9. 运行

```bash
npm install            # 只装 ws（好友房联机用）
npm start              # → http://localhost:8787
```

- 纯单机：直接打开 `index.html` 也可以（`file://` 下会自动隐藏联机入口）。
- 单文件离线版：`node tools/build-offline.mjs` → 产出 `transport-ship.html`
  （需要 esbuild，可用 `ESBUILD_PATH` 指定）。
- 数值体检：`node tools/ttk.mjs`（改完 `arsenal.js` 必跑）。
- 局域网 1v1：`npm start` 后，对方访问 `http://<你的内网IP>:8787`，
  `GET /duel-server.json` 会返回可用地址列表。

### 操作

| 动作 | 键 |
|---|---|
| 移动 / 静步 / 冲刺 | WASD / Shift / X |
| 下蹲 / 跳跃 | C / 空格 |
| 射击 / 瞄准（近战为重击） | 鼠标左键 / 右键 |
| 武器槽 / 快切 / 换弹 | 1–4 / Q / R |
| 检视 / 换装 | Y / B |
| 战绩 / 暂停 | Tab / Esc |

触屏设备会自动显示虚拟摇杆与开火键。

## 12. 一句话总结

**机制层已经过线，系统层还没开始。** 所有改动按这个顺序：
先补反馈（让 91.8 可被读懂）→ 再修数值（杀掉假选择）→ 再动循环（让计时器有意义）→ 最后才谈长线。
顺序反了，上面每一层都会白做。
